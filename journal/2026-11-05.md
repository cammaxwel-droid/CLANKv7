# 2026-11-05 — first RNG step

## What we built

Picked C++11 and sketched TriFlow, a deterministic PRNG with three evolving
64-bit lanes. Each output combines the lanes' mixed values, their exact
integer average, and the call count.

## What we learned

Averages are not automatically "more random": averaging tends to pull values
toward the center. TriFlow therefore uses the average as one ingredient and
mixes it with the lane values before returning an output. That is a design
experiment, not evidence that the generator is unbiased or secure.

The seed fixes the whole sequence. Running several lanes in one `next()` call
does not create new entropy or require separate threads.

## Next experiments

Add dedicated bias, runs, and correlation tests; compare against known
generators; only then decide whether the design needs another round of changes.

## Follow-up: roadmap work

The TriFlow prototype was merged to `main`. This follow-up added broader
non-certifying statistical checks, bounded-number examples for dice and toy
reels, and a speed-only comparison against `std::mt19937_64`.

The fixed-seed smoke checks passed for the sampled byte counts, bit balance,
and adjacent low-bit transitions. The bounded sampler uses rejection rather than direct modulo to avoid
introducing modulo-remainder bias when its input is uniform; this does not
prove TriFlow's output is uniform. A local benchmark run measured about
8.2 ns/output for TriFlow and 1.7 ns/output for `std::mt19937_64`; these
machine-dependent timings are speed results, not quality results.

## 2026-11-06 — support for the merged prototype

Kept the builder's generator unchanged and added regression checks around its
public interface: edge seeds, restarting a used generator, alternating the two
call forms, and copying a generator partway through its stream.

Twenty edge-seed outputs were calculated using a separate Python reference
with an unlimited-size integer sum for the average. That reference also
matched the eight original expected outputs. Fixed vectors catch accidental
changes to the sequence; reseeding checks catch forgotten state resets.
Copied generators retain the same sequence, not independent random streams.

Updated the roadmap, design notes, and test guide, including a Windows command.
The C++11 suite passed with GCC and `-Wall -Wextra -Wpedantic -Werror`; the
existing 262,144-output histogram still ranged from 921 to 1120 per bucket.
A temporary portable compiler was used because no C++ compiler was installed.
These checks protect repeatability; they do not certify randomness or security.

### Support follow-up: rejection-sampling boundaries

Brought the already-merged bounded-sampling helper into the support checkout
unchanged and added a separate edge-regression executable. Dice-sized bounds
almost never reject a raw 64-bit value, so a histogram alone misses that code
path. Large, carefully chosen bounds force discarded values and check that a
value exactly on the threshold is accepted rather than skipped. Other cases
cover repeated rejection, maximum bounds, and zero-bound errors that must leave
the generator untouched.

The original generator suite and the new edge suite both passed with the
installed MSVC compiler, `/std:c++14 /W4 /WX /EHsc /permissive-`; the code still
uses only C++11 features. No generator or sampling implementation was changed.
The separate visualizer builder's files were not edited.
