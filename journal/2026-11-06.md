# 2026-11-06 — make seed equations visible

## What changed

Added optional Quadratic bend, Rotate fold, and Cross-feed seed equations.
Every toggle starts off. The original TriFlow implementation and default
sequence remain unchanged; a separate C++11 header applies enabled equations
before the normal seed initialization.

The local browser lab uses exact BigInt arithmetic rather than rounding seeds
through JavaScript floating-point numbers. It shows the seed stages and
compares the original and experimental output with a histogram, adjacent-pair
scatter, and bit raster. Playback reveals a fixed batch, so timing never
changes the output sequence.

## What we learned

A more complicated seed equation is not automatically better. Cross-feed alone
maps both zero and the largest 64-bit seed to zero. That means those distinct
inputs replay the same output. The experiment stays opt-in, and the collision
is explained and tested rather than hidden by a convincing-looking plot.

Equations cannot manufacture entropy. The seed plus the toggle settings still
fully determines the stream. Changed-bit counts show a local transformation,
not cryptographic strength, and a repeated output is not necessarily a repeated
internal state.

- Built the optional header/tests with MSVC, `/W4`, in its C++14 mode (the source
  uses C++11 features; MSVC has no selectable C++11 mode).
- Passed the existing TriFlow regression and histogram check: the 256 high-byte
  buckets ranged from 921 to 1120 for its fixed sample.
- Passed 24 independently calculated golden seed vectors and 576 native replay
  profiles, including all toggle combinations and single-bit input seeds.
- Passed six Node test cases with no skips, including exact seed parsing,
  original output vectors, equation order, plot-statistic edge cases, and
  48 fixed seed/settings smoke profiles.
- Compared 36,864 browser-model outputs directly against the compiled C++
  implementation; all matched.
- Passed static HTML checks for local assets, script ordering, unique IDs,
  label targets, and the four canvas elements.
- Passed nine controller checks using the real math/controller code with a
  simulated DOM, canvas, and clock. These cover all toggle combinations, exact
  and oversized inputs, error-state preservation, replay/step/playback through
  batch completion, prefix metrics, hidden tabs, reduced motion, finite canvas
  dimensions, and listener stability. The final combined Node run passed all
  15 tests with no skips.

## Support-test integration

Ported the two support test files without replacing the newer visualizer docs.
The RNG regressions now cover five edge-seed golden vectors, reseeding,
interchange of `operator()` and `next()`, and copied/assigned state. A new
bounded-sampling edge test checks threshold equality and neighboring values,
maximum/power-of-two bounds, exact consumption through one or multiple
rejections, and zero-bound exceptions that preserve state.

Both ported files match the supplied support contents and passed here with
MSVC `/std:c++14 /EHsc /W4 /WX /permissive-`. The fixed histogram remains
921–1120. No generator or bounded-sampling helper changes were needed. Only
relevant usage/coverage descriptions were merged into this worktree's docs;
the source checkout was left untouched.

These regressions protect the rules for restarting and consuming the number
stream. They are not additional evidence of cryptographic security or quality.

## Browser-validation limit

The sandbox's localhost proxy blocked the browser-debugging connection. A
separate direct local-file headless render timed out without a screenshot.
The owner chose to continue with local-file checks and leave real interactive
browser testing unverified. Automated controller tests are not a substitute for
checking the actual rendering and interactions in a browser.

These are measured regression and smoke results, not certification, proof of
unpredictability, a broad collision analysis, or independent statistical review.
