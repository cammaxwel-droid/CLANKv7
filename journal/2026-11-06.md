## What changed and why

Named the existing stream `triflow-v1` and documented its exact constants,
operation order, unsigned wrapping and average in `docs/triflow-v1.md`.
The header's LF-normalized hash pins the frozen source across Windows and
Unix checkouts. Kept all 28 pre-existing expected outputs in place and copied
them into a reusable JSON fixture. Golden values were not regenerated.

Added an independent standard-library Python reference. Python can calculate
`(a + b + c) // 3` directly without overflow; C++ uses quotients and remainders
to get the same answer inside 64 bits. Comparing these two calculations helps
catch arithmetic mistakes that matching-looking random output would miss.
A separate text adapter calls the unchanged C++ engine.

Added `scripts/verify.cmd` and `scripts/verify.py` to compile and check in new,
isolated build folders. They record source hashes, HEAD plus dirty status,
tool identities, platform, exact commands, exit codes and output in JSON.
They do not download tools, alter system settings, regenerate fixtures, or
replace previous run evidence. The Windows wrapper avoids PowerShell's script
execution-policy problem. Recorded the remaining bounded milestones and
updated README/test instructions without changing the established design.

suite, clean npm consumer, licensing or publication acceptance is claimed.
